# SantaFeSL — Identidad de marca

> Documento de referencia para la identidad, posicionamiento, personalidad, comunicación y lenguaje visual de SantaFeSL.

## 1. Identidad

### Nombre
**SantaFeSL**

### Dominio
**santafesl.com**

### Significado
SantaFeSL combina:
- **Santa Fe** — origen e identidad local.
- **SL** — referencia a Software Libre.

El nombre no limita la actividad de SantaFeSL a un único producto o servicio. La marca puede abarcar software propio, servicios tecnológicos, infraestructura, servidores, herramientas, experimentos y proyectos futuros.

### Concepto de marca
> **Tecnología simple para problemas reales.**

### Descriptor
> **Software, servidores y tecnología para pequeños negocios y personas.**

## 2. Propósito

SantaFeSL existe para crear y ofrecer soluciones tecnológicas útiles, simples y accesibles que ayuden a personas y pequeños negocios a resolver necesidades concretas.

La tecnología debe estar al servicio del problema y no convertirse en un problema adicional.

## 3. Filosofía

### Simple
Preferimos soluciones sencillas, claras y mantenibles antes que arquitecturas innecesariamente complejas.

### Útil
Construimos tecnología para resolver necesidades reales.

### Cercana
La comunicación debe ser comprensible para personas que no necesariamente tienen conocimientos técnicos.

### Transparente
No prometemos capacidades, características o resultados que no podamos ofrecer.

### Libre
Valoramos el Software Libre, los estándares abiertos y las tecnologías que permiten estudiar, utilizar, modificar y mantener las soluciones de forma independiente.

### Mantenible
Preferimos tecnologías conocidas, documentadas y sostenibles a largo plazo.

### Real
SantaFeSL muestra proyectos y capacidades reales. No se utilizan afirmaciones exageradas para aparentar una escala, experiencia o infraestructura que no existe.

## 4. Público

### Público principal
- Kioscos.
- Almacenes.
- Pequeños comercios.
- Emprendedores.
- Profesionales independientes.
- Personas que necesitan una solución tecnológica concreta.

### Público secundario
- Pequeñas organizaciones.
- Personas interesadas en servidores e infraestructura.
- Otros desarrolladores.
- Personas interesadas en Software Libre.
- Usuarios que necesiten asistencia tecnológica.

## 5. Posicionamiento

SantaFeSL no busca presentarse como una gran consultora tecnológica ni como una empresa corporativa.

La marca representa a una persona que construye software, administra infraestructura y desarrolla soluciones tecnológicas para problemas concretos.

> **Entender el problema, elegir una solución razonable y mantenerla simple.**

## 6. Pilares

### Productos
Software propio desarrollado para resolver necesidades concretas.

### Servicios
Trabajo tecnológico realizado para otras personas o negocios.

### Laboratorio
Proyectos, experimentos, herramientas, investigaciones y soluciones que no necesariamente son productos comerciales.

## 7. Personalidad

SantaFeSL debe sentirse:
- Simple.
- Cercana.
- Profesional.
- Técnica.
- Transparente.
- Útil.
- Humana.

Debe evitar sentirse:
- Corporativa.
- Pretenciosa.
- Artificial.
- Excesivamente técnica.
- Agresivamente comercial.
- Llena de términos de marketing.
- Más grande de lo que realmente es.

## 8. Tono

El tono debe ser:
- Claro.
- Directo.
- Humano.
- Profesional.
- Honesto.

Puede utilizarse primera persona cuando corresponda: “Estoy desarrollando…”, “Construí…”, “Este proyecto nació para…”.

## 10. Identidad visual

La identidad visual utiliza principalmente:
- Azul.
- Rojo.
- Blanco.
- Grises neutros.

El azul es el color principal. El rojo funciona como color de acento y acción.

## 12. Tipografía

**Inter** será la familia principal.

No se utilizarán múltiples familias salvo que exista una razón concreta.

## 13. Iconografía

Se utilizará **Font Awesome**.

Los iconos deben complementar información, no decorar por decorar.

## 14. Logo

El logotipo priorizará el nombre **SantaFeSL**.

Se explorará una versión donde `SantaFe` use azul y `SL` rojo. La decisión final deberá validarse visualmente.

No se utilizarán símbolos genéricos de servidores, computadoras, nubes o código como elemento principal.

## 15. Imágenes

Se priorizarán imágenes reales:
- capturas de aplicaciones;
- fotografías de infraestructura;
- servidores;
- redes;
- herramientas;
- proyectos;
- diagramas;
- fotografías propias.

Evitar el uso excesivo de stock genérico.

## 16. Interfaz

La interfaz debe ser:
- Responsive.
- Mobile-first.
- Accesible.
- Clara.
- Rápida.
- Consistente.
- Fácil de mantener.

Se utilizará Bootstrap 5 como base visual.

No se utilizarán estilos inline ni personalizaciones innecesarias.

## 17. Diseño

Evitar:
- exceso de sombras;
- gradientes decorativos innecesarios;
- glassmorphism;
- animaciones excesivas;
- sliders;
- efectos que dificulten la lectura;
- exceso de tarjetas.

Priorizar:
- espacios en blanco;
- jerarquía tipográfica;
- contraste;
- bordes discretos;
- sombras sutiles;
- componentes consistentes;
- contenido real.

## 18. Modo oscuro

No se implementará inicialmente salvo necesidad concreta.

## 19. Regla principal

> **¿Esto hace que SantaFeSL sea más claro, útil y confiable?**

Si no aporta valor, debe considerarse innecesario.
